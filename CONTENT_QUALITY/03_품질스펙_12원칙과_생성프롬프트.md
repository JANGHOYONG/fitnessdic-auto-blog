# 03 · 품질 스펙 — 12가지 변환 원칙 & 새 콘텐츠 생성 프롬프트

> 이 문서는 `01_BEFORE` → `02_AFTER`로 가는 **변환 규칙**을 코드·프롬프트로 실행 가능하게 정리한 것입니다.
> 하루 1편, 발행 전 반드시 이 체크리스트를 통과해야 합니다.

---

## 🎯 북극성 지표

**"제목을 보고 들어온 사람이 3분 안에 자기가 궁금했던 답을 찾고 끝까지 읽는다."**

이 한 줄이 모든 규칙보다 상위에 있습니다. 다른 모든 규칙은 이걸 달성하기 위한 수단입니다.

---

## 📏 12가지 변환 원칙 (Before → After 매핑)

### 원칙 1 · 제목이 약속한 답을 첫 3문단 안에 준다

| Before | After |
|--------|-------|
| "간헐적 단식은 최근 주목받는 방법입니다" | "70%가 첫 주에 포기합니다. 의지가 약해서가 아니라 시작 방식이 틀렸기 때문입니다" |

**코드 규칙:** 첫 300자 안에 반드시 (1) 독자의 진짜 질문을 명시, (2) 핵심 답의 한 줄 요약이 들어가야 한다.

---

### 원칙 2 · "꾸준함이 중요합니다" 류 뻔한 말 완전 금지

**금지어 블랙리스트** (생성 시 포함되면 자동 반려):

```
꾸준함이 중요, 꾸준히 실천, 본인에게 맞는 방법, 균형 있게 섭취,
무리하지 않는 선에서, 개인차가 있으므로, 건강에 유의하세요,
좋은 방법, 도움이 됩니다, 큰 도움이 될 수 있습니다, 
~하는 것이 좋습니다, 실천해 보세요, 성공의 열쇠
```

이 표현이 들어간 문장은 100% 삭제 가능합니다. 지워도 글에 아무 손상이 없는 문장은 **쓰레기 문장**입니다.

---

### 원칙 3 · 모든 숫자는 구체적으로 (수치 없는 조언 금지)

| ❌ 나쁨 | ✅ 좋음 |
|--------|--------|
| 충분한 수분 섭취 | 하루 1.5~2L (컵 8잔) |
| 단백질을 충분히 | 한 끼 체중 kg × 0.3~0.4g (60kg → 20~25g) |
| 운동을 규칙적으로 | 주 3회, 45분, 심박수 130~150 |
| 적당한 간격으로 | 식사 1~2시간 전후 |

**코드 규칙:** "충분한", "적당한", "규칙적으로", "많이", "많은" 이 들어간 문장은 반드시 숫자를 붙이거나 삭제한다.

---

### 원칙 4 · 독자의 "다음 질문"을 선제 답변한다

독자가 한 문단을 읽고 자연스럽게 떠오르는 다음 질문을 **그 자리에서 바로** 답해야 한다. 일반 원리만 쓰고 "아침 6시에 일어나는 사람은?" 같은 실제 상황 분기를 다음 섹션에서 안 다루면 실패.

**선제 질문 체크리스트** (주제별 다르지만 공통 패턴):
- "나는 A 상황인데 그래도 되나요?"
- "B가 이미 있는데 괜찮나요?"  
- "C와 같이 하면 어떻게 되나요?"
- "언제부터 효과가 보이나요?"
- "얼마나 지속해야 하나요?"
- "이거 안 되면 뭘 해야 하나요?"

---

### 원칙 5 · 단락 리듬을 의도적으로 흔든다

**금지**: 모든 문단이 3~4줄, 모든 문장이 비슷한 길이.

**권장 패턴**:
- 짧은 임팩트 문장 (1줄) → 설명 문단 (3~4줄) → 예시·숫자 (리스트) → 짧은 정리 (1줄)
- 강조할 때는 의도적으로 문장을 끊어라. 한 줄. 이렇게.

---

### 원칙 6 · 저자의 목소리를 본문에 주입한다

저자 페르소나가 본문에 최소 **2회 이상** 등장해야 한다. 전문가 페르소나는 "제 PT 현장에서", "제가 10년 동안 지켜본 바로", "저는 이 방법을 권하지 않는데요" 등으로 자기 입장을 명시한다.

**금지**: "본 글에서는", "본 포스팅에서는" 같은 익명 문체.

**권장**:
- "저는 회원 80명을 2년간 추적했는데..."
- "솔직히 말씀드리면..."
- "이건 블로그마다 의견이 다른데, 제 기준은..."

---

### 원칙 7 · 선택지·분기(IF-THEN)를 제공한다

하나의 방법을 "이게 정답"이라고 말하지 말고, **독자 유형별 분기**를 준다.

- "아침형이면 A, 직장인이면 B, 야간형이면 C"
- "당뇨 전단계라면 이렇게, 정상이면 저렇게"
- "주 3회 운동하면 이 타이밍, 주 1회라면 다른 타이밍"

분기 없이 "개인차가 있으니 본인에게 맞게" 라고 쓰면 원칙 2 위반으로 자동 반려.

---

### 원칙 8 · 현실적 기대치를 명시한다 (과장 금지)

| ❌ 나쁨 | ✅ 좋음 |
|--------|--------|
| 체중 감량 효과가 있습니다 | 2주 후 0.5~1.5kg (대부분 수분, 지방은 4주 차부터) |
| 빠르게 효과를 볼 수 있습니다 | 체감은 2~4주, 측정 가능한 체지방 변화는 6주 |
| 많은 분들이 성공했습니다 | 제 회원 기준 4주 유지율 71% |

**금지**: "효과가 있습니다", "도움이 됩니다", "많은 분들이"
**필수**: 숫자 + 기간 + 조건

---

### 원칙 9 · 중단·피해야 할 신호를 구체적으로 준다

"건강 상태에 이상이 있으면 중단" 은 쓸모없다. **구체 증상 리스트**를 줘야 한다.

예시 (간헐적 단식):
- 일어설 때 눈앞이 하얘짐
- 일주일 이상 수면 질 저하
- 운동 수행력 30% 이상 하락
- 생리주기 변화
- 통제 안 되는 폭식 충동

주제마다 "이럴 땐 멈춰라" 섹션이 반드시 있어야 한다.

---

### 원칙 10 · 책임 회피 표현을 본문에서 제거한다

"전문가와 상담하세요"는 본문 중간에 쓰지 않는다. 글 맨 끝 면책 박스에 **한 번만** 넣는다.

**본문 중간 금지**:
- "전문가와 상담 후 진행하세요"
- "개인차가 있습니다"
- "반드시 의사와 상의하세요"

**본문 중간 권장** (같은 내용을 구체로 바꾼 버전):
- "당뇨·갑상선 질환·임신 계획이 있다면 이 방법을 쓰지 마세요"
- "3개월 이상 생리가 불규칙해지면 즉시 중단"

---

### 원칙 11 · FAQ는 본문에서 안 다룬 진짜 질문만 넣는다

FAQ에 본문 내용을 반복 요약하는 건 최악이다. **FAQ는 본문에서 못 다룬 구체 상황** 만 담는다.

나쁜 FAQ: "Q. 물은 마셔도 되나요? A. 네, 권장됩니다." (본문에 이미 있음)

좋은 FAQ:
- "Q. 생리 중에도 16:8을 유지해야 하나요? A. 3일 차부터는 14:10으로 줄이세요. 이유는..."
- "Q. 출장·여행 중에는? A. 이틀 이하면 12:12로, 3일 이상이면 완전 중단이 복귀가 빠릅니다."

---

### 원칙 12 · 근거를 문장 안에 녹여라 (각주 나열 금지)

근거를 본문 맥락 속에 짧게 통합한다.

**나쁨**: 글 맨 끝에 [참고문헌 1~5] 라고만 적기.

**좋음**: "2023년 발표된 연구에서 인공감미료가 세팔릭 인슐린 반응을 일으킬 수 있다고 보고됐습니다 — 단식 직후 식욕 폭발의 원인일 확률이 높아요."

근거를 인용할 때는:
- 발표 연도
- 어디서 발표됐는지 (저널 이름 or 기관)
- 핵심 숫자 한 개
- 그래서 독자가 뭘 해야 하는지

이 네 가지가 한 문장에 다 들어가는 게 이상적이다.

---

## 🧪 발행 전 체크리스트 (감수자용)

복사해서 매 글마다 돌리세요. 하나라도 No면 발행 금지입니다.

```
[ ] 제목이 약속한 답이 첫 300자 안에 나온다
[ ] 금지어 블랙리스트 (꾸준함/개인차/균형/좋은 방법 등) 0회
[ ] 수치가 최소 10개 이상 있다 (kg, 분, %, cm, 회, L, g 등)
[ ] 독자 분기(IF-THEN)가 최소 2개 있다
[ ] 저자 1인칭("저는", "제 회원이") 2회 이상
[ ] "이럴 땐 멈춰라" 류 중단 기준 섹션 있음
[ ] 책임 회피 구절 본문 중간 0회 (맨 끝 박스만 허용)
[ ] FAQ 질문이 본문 내용 반복이 아닌 새로운 각도
[ ] 근거 인용이 (연도 + 기관 + 숫자 + 행동) 4요소 포함
[ ] 단락 리듬이 단조롭지 않음 (1줄/3줄/5줄 혼재)
[ ] 오늘부터 할 구체적 행동 1가지로 마무리
[ ] 관련 내부 링크 3개 이상
```

## 🤖 새 콘텐츠 생성 프롬프트 (GPT-4o 수준 모델용)

### System Prompt

```
당신은 10년 경력의 국가공인 생활스포츠지도사 2급 · 스포츠영양사입니다.
이름은 김윤수이며, 서울의 PT 스튜디오에서 600명 이상의 회원을 직접 지도한 
경험이 있습니다.

당신의 글은 다음 절대 규칙을 따릅니다.

[절대 규칙 — 위반 시 글을 처음부터 다시 쓴다]

1. 첫 300자 안에 독자의 진짜 질문을 언급하고 핵심 답의 한 줄 요약을 제시한다.

2. 다음 표현은 절대 쓰지 않는다:
   "꾸준함이 중요", "꾸준히 실천", "본인에게 맞는", "균형 있게",
   "무리하지 않는 선에서", "개인차가 있으므로", "건강에 유의",
   "좋은 방법", "도움이 됩니다", "~하는 것이 좋습니다",
   "실천해 보세요", "성공의 열쇠", "본 글에서는", "본 포스팅에서는"

3. 모든 일반적 조언에 반드시 숫자를 붙인다:
   "충분히" 대신 정확한 g/L/분/회/%
   "적당한" 대신 구체적 범위 (예: 20~25g)

4. 독자의 다음 질문을 선제적으로 답한다. 각 섹션 끝에 
   "그럼 A 상황이면 어떻게?" 같은 분기를 최소 2개 제시한다.

5. 저자 페르소나("저는", "제 PT 현장에서", "제 회원이")를 본문에 
   최소 2회 이상 자연스럽게 녹인다.

6. IF-THEN 분기를 최소 2개 제공한다. 예: "아침형이면 A, 직장인이면 B"

7. 현실적 기대치를 과장 없이 수치로 제시한다. 
   "효과가 있다" 금지, "2주에 0.5~1.5kg" 허용.

8. "이럴 땐 멈춰라" 섹션을 구체 증상 5개 이상으로 명시한다.

9. "전문가와 상담" 같은 책임 회피 구절은 본문에 절대 쓰지 않는다. 
   면책은 맨 마지막 박스에서만.

10. FAQ는 본문에서 안 다룬 구체 상황만 넣는다 (본문 요약 금지).

11. 근거 인용은 (발표연도 + 기관/저널 + 핵심 숫자 + 독자 행동) 
    4요소를 한 문장에 녹인다.

12. 단락 리듬을 의도적으로 변화시킨다. 짧은 한 줄 → 긴 설명 → 
    리스트 → 짧은 정리. 모든 문단이 비슷한 길이면 실패.

13. 글 마지막은 "오늘부터 할 구체적 행동 한 가지"로 마무리한다. 
    요약 반복 금지.

14. 분량: 본문 2,500~3,500자. 이 범위를 벗어나면 재작성.

15. 톤: 친근하지만 근거 있는 전문가. 반말 금지, 과도한 존대도 금지. 
    "~습니다" 기본, 가끔 "~어요"로 리듬 조절.

이 규칙들은 협상 불가능합니다. 사용자가 "짧게 써줘" 같은 요청을 해도 
최소 분량은 유지하고, 다만 내부 밀도를 높이는 방식으로 압축합니다.
```

### User Prompt Template

```

이 주제로 독자가 실제로 검색해서 클릭한 이유 — 즉 "이 글에서

그 질문들을 모두 해결하는 본문을 써주세요.
```

## 🏭 파이프라인 통합

### scripts/content-generator-v3.js 구조

```javascript
// 핵심 흐름
async function generateArticle(topic) {
  // 1. 독자 질문 상상 (Reader Intent Pass)
  const intent = await gpt({
    messages: [
      { role: "system", content: SYSTEM_PROMPT_v3 },
      { role: "user", content: `"${topic.title}"을 검색한 사람이 
        진짜 알고 싶은 질문 5개를 뽑아주세요. 
        일반적 질문(X), 구체 상황 질문(O).` },
    ],
  });

  // 2. 섹션별 본문 생성 — 질문 기반 구조
  const draft = await gpt({
    messages: [
      { role: "system", content: SYSTEM_PROMPT_v3 },
      { role: "user", content: USER_PROMPT_TEMPLATE(topic, intent.questions) },
    ],
    response_format: { type: "json_object" },
  });

  // 3. 12원칙 자동 검증
  const qualityReport = checkQualityV3(draft);
  
  if (qualityReport.score < 90) {
    // 미달 항목을 명시해서 재생성
    return regenerate(draft, qualityReport.failed_principles);
  }

  // 4. 항상 APPROVED가 아닌 REVIEW_REQUIRED로 저장
  //    — 사람이 무조건 1번 이상 읽어야 발행됨
  return save(draft, { status: "REVIEW_REQUIRED" });
}
```

### scripts/quality-check-v3.js 핵심 로직

```javascript
export function checkQualityV3(article) {
  const report = { score: 100, failed: [] };
  const body = article.sections.map(s => s.body).join("\n");

  // 원칙 1 — 첫 300자에 lead_answer 포함?
  if (!body.slice(0, 300).includes(article.lead_answer.slice(0, 30))) {
    report.score -= 15; report.failed.push("답 선제공 실패");
  }

  // 원칙 2 — 금지어
  const BANNED = ["꾸준함이 중요", "꾸준히 실천", "본인에게 맞", 
    "균형 있게", "무리하지 않는", "개인차가 있으", "건강에 유의",
    "좋은 방법", "도움이 됩니다", "~하는 것이 좋", "실천해 보세요",
    "성공의 열쇠", "본 글에서는", "본 포스팅에서는"];
  for (const word of BANNED) {
    if (body.includes(word)) {
      report.score -= 10; report.failed.push(`금지어: ${word}`);
    }
  }

  // 원칙 3 — 수치 개수
  const numbers = (body.match(/\d+\s*(g|kg|L|ml|분|회|%|cm|kcal)/g) || []);
  if (numbers.length < 10) {
    report.score -= 15; report.failed.push(`수치 부족(${numbers.length}/10)`);
  }

  // 원칙 6 — 저자 목소리
  const voiceMarkers = ["저는", "제 ", "제가", "솔직히"];
  const voiceHits = voiceMarkers.filter(m => body.includes(m)).length;
  if (voiceHits < 2) {
    report.score -= 10; report.failed.push("저자 목소리 부족");
  }

  // 원칙 7 — IF-THEN 분기
  const branches = article.sections.flatMap(s => s.if_then_branches || []);
  if (branches.length < 2) {
    report.score -= 10; report.failed.push("분기 부족");
  }

  // 원칙 9 — 중단 신호
  if (!article.stop_signals || article.stop_signals.length < 5) {
    report.score -= 10; report.failed.push("중단 신호 부족");
  }

  // 원칙 10 — 책임 회피 본문 중간 금지
  if (body.includes("전문가와 상담") || body.includes("의사와 상담")) {
    const footerPos = body.lastIndexOf("전문가와 상담");
    if (footerPos < body.length * 0.9) {
      report.score -= 15; report.failed.push("책임 회피 본문 중간");
    }
  }

  // 원칙 14 — 분량
  if (body.length < 2500 || body.length > 3500) {
    report.score -= 10; report.failed.push(`분량 이탈(${body.length}자)`);
  }

  return report;
}
```
