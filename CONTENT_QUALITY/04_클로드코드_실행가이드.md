# 04 · 클로드 코드 실행 가이드

> 이 문서는 `CONTENT_QUALITY/01~03` 문서를 실제 코드로 반영하기 위해
> 클로드 코드(Claude Code)에 어떻게 명령할지 정리합니다.

---

## 🎯 전체 흐름

```
[지금] 3개 MD 파일 = 참고 문서
                  ↓
        클로드 코드가 MD를 읽고
                  ↓
        실제 .js / .yml / .tsx 파일 생성·수정
                  ↓
[결과] 하루 1편 고품질 자동 생성 파이프라인
```

---

## 📋 실행 3단계

### 1단계 — 터미널에서 프로젝트 열기

맥 기준:

```bash
cd ~/다이어트\ 블로그       # 실제 로컬 경로에 맞게 변경
claude                     # 또는 설치한 바이너리명
```

(프로젝트 경로가 `~/BLOG\ AUTO` 같이 다르면 그 경로로)

클로드 코드 프롬프트 창이 뜨면 2단계로 넘어갑니다.

### 2단계 — 마스터 프롬프트 붙여넣기

아래 "마스터 프롬프트" 전체를 복사해서 클로드 코드 프롬프트 창에 붙여넣고 Enter.

### 3단계 — 클로드 코드가 질문하면 답하기

클로드 코드는 단계별로 작업하면서 "이렇게 고쳐도 될까요?" 라고 물어볼 겁니다.
- 코드 수정 제안 → `y` (확인) 또는 수정 요청
- 각 단계 완료 시 → "다음 단계" 또는 `continue`
- 막히면 → `03 품질스펙 파일을 다시 읽어봐` 라고 재지시

## 🧩 마스터 프롬프트 (이걸 복사해서 붙여넣으세요)

````
다이어트 블로그의 콘텐츠 자동 생성 품질을 근본적으로 개선하는 작업이야.
지금부터 아래 순서대로 진행해줘.

────────────────────────────────
STEP 0 — 맥락 파악 (먼저 이것부터)
────────────────────────────────

아래 3개 파일을 순서대로 Read 도구로 읽어서 맥락을 파악해.

1. CLAUDE.md
   → 프로젝트 전체 구조, 기존 스크립트 이름, DB 스키마 개요

2. CONTENT_QUALITY/03_품질스펙_12원칙과_생성프롬프트.md
   → 이번 작업의 핵심 스펙. 12원칙, System/User 프롬프트,
      quality-check-v3 검증 로직, 새 케이던스, 성공 지표.

3. CONTENT_QUALITY/02_AFTER_친한전문가톤_완성본.md
   → 목표 품질 수준의 실제 예시. 이 글의 톤·구조·밀도를
      재현할 수 있는 파이프라인을 만드는 게 목표야.

3개를 다 읽고 나서 "맥락 파악 완료" 라고 확인한 다음 STEP 1로 넘어가.

────────────────────────────────
STEP 1 — 새 콘텐츠 생성기 v3 구현
────────────────────────────────

scripts/content-generator-v3.js 를 새로 만들어.

요구사항:
- 기존 scripts/content-generator.js 구조는 참고만 하고 로직은 새로 짜
- OpenAI 호출 모델: gpt-4o (gpt-4o-mini 아님, 품질 중요)
- System Prompt: 03 파일의 "System Prompt" 섹션을 그대로 사용
- User Prompt: 03 파일의 "User Prompt Template" 을 사용
- 응답 형식: JSON (response_format: { type: "json_object" })
  필드: reader_questions, hook, lead_answer, sections[],
        stop_signals, realistic_expectations, common_mistakes,
        today_action, faq, sources
- 섹션별 본문은 마크다운, 이미지는 Pexels API로 섹션마다 1장씩
- 생성 후 Prisma 저장 시 상태는 반드시 "REVIEW_REQUIRED"
  (기존 auto-APPROVED 로직 제거)
- 주제는 TopicQueue에서 priority 높은 순서로 1건만 뽑아서 처리

파일 생성 후 내용을 나한테 보여주고 OK 받은 뒤 다음 STEP.

────────────────────────────────
STEP 2 — 품질 검증기 v3 구현
────────────────────────────────

scripts/quality-check-v3.js 를 새로 만들어.

요구사항:
- 03 파일의 "quality-check-v3.js 핵심 로직" 코드 블록을 기반으로 구현
- export function checkQualityV3(article) 시그니처
- 반환: { score: number, failed: string[] }
- 12원칙 중 자동 검증 가능한 9개 원칙 체크:
  (1) 첫 300자에 lead_answer 포함 여부
  (2) 금지어 블랙리스트 14개 단어
  (3) 수치 최소 10개 (g|kg|L|ml|분|회|%|cm|kcal)
  (6) 저자 목소리 마커 2개 이상
  (7) IF-THEN 분기 2개 이상
  (9) stop_signals 5개 이상
  (10) "전문가와 상담" 본문 중간 금지
  (14) 본문 2,500~3,500자
- score < 90 이면 content-generator-v3 가 재생성 요청하도록 연동

파일 생성 후 내용을 나한테 보여주고 OK 받은 뒤 다음 STEP.

────────────────────────────────
STEP 3 — 케이던스 축소 (하루 1편)
────────────────────────────────

GitHub Actions 워크플로우를 3개 수정해.

(A) .github/workflows/auto-publish.yml
- cron: 기존 5회/일 → 1회/일 (KST 18:00 = UTC 09:00)
- PUBLISH_LIMIT=1 유지
- APPROVED 상태 중 publishedAt 없는 1건을 PUBLISHED로 전환

(B) .github/workflows/daily-drafts.yml
- 기존 4건 → 1건 생성
- content-generator.js 호출 → content-generator-v3.js 로 교체
- cron: KST 06:00 (UTC 21:00 전날) 유지
- DAILY_DRAFT_COUNT 환경변수 = "1"

(C) .github/workflows/quality-audit.yml
- 기존 유지 (주 1회 PUBLISHED 품질 재감사)
- 내부에서 checkQualityV3 호출하도록 변경

수정 후 diff 를 보여주고 OK 받은 뒤 다음 STEP.

────────────────────────────────
STEP 4 — Prisma 스키마·마이그레이션
────────────────────────────────

prisma/schema.prisma 확인:
- PostStatus enum 에 REVIEW_REQUIRED 가 있는지
- 없으면 추가하고 npx prisma migrate dev --name add_review_status 실행
- Post 모델에 qualityScore Int? 필드 있는지 확인, 없으면 추가

확인·수정 결과 보고.

────────────────────────────────
STEP 5 — 어드민 감수 페이지 검증
────────────────────────────────

src/app/(admin)/review/page.tsx 확인:
- REVIEW_REQUIRED 글이 목록에 뜨는지
- 각 글의 qualityScore, failed_principles 를 보여주는지
- 승인(APPROVED)·반려(REJECTED) 버튼이 작동하는지

없으면 03 파일의 "발행 전 체크리스트" 를 감수자 UI 에
표시하는 형태로 만들어줘. 각 항목을 체크박스로 렌더하고,
전부 체크됐을 때만 [승인] 버튼이 활성화되도록.

────────────────────────────────
STEP 6 — 샘플 실행 (검증)
────────────────────────────────

로컬에서 다음 명령을 실행해:

DATABASE_URL="..." \
OPENAI_API_KEY="..." \
PEXELS_API_KEY="..." \
node scripts/content-generator-v3.js --topic="스쿼트 제대로 하는 법과 흔한 실수"

생성 결과를 CONTENT_QUALITY/05_v3샘플출력.md 로 저장해서 보여줘.

그 결과가 02_AFTER 파일의 품질 수준과 비슷한지 내가 판단할 거야.
- 비슷하면 → 커밋 + 푸시
- 부족하면 → 어느 원칙이 약한지 역추적하고 프롬프트 보강

────────────────────────────────
체크포인트
────────────────────────────────

각 STEP 완료 시 다음 질문에 답해줘:
1. 이 단계에서 수정한 파일 목록
2. 발생한 이슈 / 건너뛴 것 (있다면 이유)
3. 다음 단계 진행 전 내가 알아야 할 것

모르겠는 부분이 있으면 멋대로 결정하지 말고 나한테 물어봐.
모든 코드 변경은 커밋 전에 내 확인을 거쳐.
````

## 🛟 자주 발생하는 이슈

### Q. "OpenAI API에 response_format이 없다고 에러나요"

GPT-4o가 아닌 구모델이면 JSON 모드를 지원 안 함. `gpt-4o-2024-08-06` 이상을 쓰도록 모델명을 명시.

### Q. "Pexels 이미지가 주제와 동떨어져요"

v3 프롬프트에 `"image_query": "..."` 필드를 추가하라고 클로드 코드에 지시. 영어로 구체적 키워드 ("squat form correction woman gym" 같이).

### Q. "quality-check에서 수치가 부족하다고 계속 반려돼요"

System Prompt에 **"모든 조언에 반드시 정확한 숫자를 붙여라. 못 붙이는 조언은 쓰지 마라."** 라고 한 줄을 더 강조해 달라고 요청.

### Q. "감수자가 매일 30분 내기 힘들어요"

03 파일의 "하루 1편" 타협안:
- 평일 감수 → 평일 발행
- 주말 감수 못하면 → **발행 없음, 공백 유지**. 이게 저품질보다 AdSense에 유리.

```
[ ] 샘플 출력(스쿼트 주제) 이 2,500자 이상 + 금지어 0 + 수치 10개+
[ ] DB에 새 글이 REVIEW_REQUIRED 로 저장됨
[ ] /admin/review 에서 해당 글이 체크리스트와 함께 보임
[ ] 내가 눈으로 읽었을 때 "02_AFTER 수준이다" 라는 판단이 듦
```
