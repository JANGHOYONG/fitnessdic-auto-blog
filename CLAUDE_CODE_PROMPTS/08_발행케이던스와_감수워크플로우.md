# 08 · 발행 케이던스 & 감수 워크플로우

## 🎯 목표

"하루 5건 자동 발행 → 하루 2건 감수 발행"으로 케이던스를 전환한다. 사람(운영자) 감수가 매일 반드시 개입하도록 **감수 큐 어드민 페이지**와 **승인 토큰**을 도입한다. 이 체계가 완성되면 AdSense 재심사 시 '에디토리얼 프로세스가 있는 사이트'로 인식된다.

| 시각 | 워크플로우 | 동작 |

- APPROVED 2건 미만 시 Slack 알림 (또는 이메일)

## 📋 구체 지시사항

### 1) `.github/workflows/daily-drafts.yml`

```yaml
name: Daily Drafts (초안 4건)
on:
  schedule:
    - cron: "0 21 * * *"   # UTC 21:00 = KST 06:00
  workflow_dispatch: {}
jobs:
  draft:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 22 }
      - run: npm ci
      - run: npx prisma migrate deploy
      - env:
          OPENAI_API_KEY: ${{ secrets.OPENAI_API_KEY }}
          PEXELS_API_KEY: ${{ secrets.PEXELS_API_KEY }}
          DATABASE_URL: ${{ secrets.DATABASE_URL }}
          DAILY_DRAFT_COUNT: "4"
        run: node scripts/content-generator.js
```

### 2) `.github/workflows/auto-publish.yml` (수정)

```yaml
name: Auto Publish (감수 통과 1건)
on:
  schedule:
    - cron: "30 0 * * *"   # UTC 00:30 = KST 09:30
    - cron: "0 12 * * *"   # UTC 12:00 = KST 21:00
  workflow_dispatch: {}
jobs:
  publish:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 22 }
      - run: npm ci
      - env:
          DATABASE_URL: ${{ secrets.DATABASE_URL }}
          REVALIDATE_SECRET: ${{ secrets.REVALIDATE_SECRET }}
          NEXT_PUBLIC_SITE_URL: ${{ secrets.NEXT_PUBLIC_SITE_URL }}
          PUBLISH_LIMIT: "1"
        run: node scripts/publisher.js
```

### 3) `.github/workflows/quality-audit.yml`

```yaml
name: Weekly Quality Audit
on:
  schedule:
    - cron: "0 18 * * 6"   # UTC 일요일 18:00 = KST 월요일 03:00
  workflow_dispatch: {}
jobs:
  audit:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 22 }
      - run: npm ci
      - env:
          DATABASE_URL: ${{ secrets.DATABASE_URL }}
        run: node scripts/quality-audit.js
```

`quality-audit.js`는 기존 PUBLISHED 글을 `checkQuality()`로 재검사해 85점 미만은 `REVIEW_REQUIRED` 상태로 되돌리고, 어드민 큐에 올린다.

### 4) 어드민 감수 페이지

```tsx
// src/app/(admin)/review/page.tsx
export default async function ReviewQueue() {
  const posts = await prisma.post.findMany({
    where: { status: { in: ["REVIEW_REQUIRED", "APPROVED"] } },
    orderBy: { createdAt: "desc" },
    take: 50,
    include: { author: true },
  });
  // 테이블: 제목 · 카테고리 · 상태 · 품질점수 · 저자 · [보기] [승인] [반려]
}
```

승인·반려는 API 호출로 처리하고, 승인 시 `APPROVED`로, 반려 시 `REJECTED` + 사유 노트 기록.

### 5) `publisher.js` 수정

```javascript
const limit = parseInt(process.env.PUBLISH_LIMIT || "1");
const candidates = await prisma.post.findMany({
  where: { status: "APPROVED" },
  orderBy: [{ qualityScore: "desc" }, { createdAt: "asc" }],
  take: limit,
});
for (const p of candidates) {
  await prisma.post.update({
    where: { id: p.id },
    data: { status: "PUBLISHED", publishedAt: new Date() },
  });
  // 캐시 재검증
  await fetch(`${process.env.NEXT_PUBLIC_SITE_URL}/api/revalidate?secret=${process.env.REVALIDATE_SECRET}&path=/post/${p.slug}`);
}
```

### 6) `/admin` 접근 보호

`src/middleware.ts`에 Basic Auth 또는 쿠키 기반 인증 추가. `.env`의 `ADMIN_USER`, `ADMIN_PASS` 사용. 2FA는 Vercel의 Deployment Protection으로 대체 가능.

### 7) 알림 (선택)

`scripts/notify.js`를 두고 Slack Incoming Webhook 또는 이메일(SendGrid/Resend)로:
- `APPROVED` 큐가 2건 미만이 된 순간
- `REVIEW_REQUIRED`가 10건 이상 적체됐을 때
- 일일 발행 실패 시

## 🧠 체크포인트 — AdSense 재심사 타이밍

새 케이던스로 **30일 이상** 유지하여 다음 조건을 모두 충족한 뒤 재심사를 넣는다:

- 품질 기준선 통과 글 **최소 60건 누적**
- About / Privacy / Contact / Disclaimer / Authors 페이지 모두 존재
- 저자 프로필 3명 이상, 각 글에 실명 바이라인
- 구조화 데이터(JSON-LD) 전 페이지 적용
- Core Web Vitals 모두 Good
- 30일간 부적절 콘텐츠(성인·폭력·저작권 침해) 0건
- 광고 자리가 지정돼 있더라도 아직 광고 유닛을 **본문 50% 이하**로 유지

재심사 신청 직전 체크리스트:
1. 3~5개 글을 랜덤 선택해서 저자 이름으로 구글 검색 → Person Knowledge 후보 인식 여부
2. `site:example.co.kr` 검색 결과가 **최소 40건 이상** 색인됨
3. `rich-results-test` 에서 Article·FAQ·Breadcrumb 모두 유효
4. 사이트 체류시간 평균 2분 이상 (GA4)

이 모든 조건이 충족됐을 때만 재심사 요청. 한 번 반려되면 다음 재심사까지 감점되므로 **확실할 때 단 한 번만** 넣는다.
